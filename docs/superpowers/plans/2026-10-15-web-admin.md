# Web Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users configure inkdoor from a password-protected web admin served on the same port as the Kindle image, safely on a plain-HTTP home network.

**Architecture:** `inkdoor serve` becomes a Flask app served by Waitress, plus the existing render loop in a background thread that is the only code that renders. Security-sensitive pieces live in small focused modules (`net.py` for outbound fetches, `web/auth.py`, `web/hosts.py`, `config_edit.py`, `files.py`) with unit tests; Flask routes stay thin. `config.toml` stays the single source of truth and is edited as raw TOML.

**Tech Stack:** Python 3.10+, Flask 3, Jinja2 (autoescape), Waitress 3, tomli-w, requests, Pillow, pytest.

**Spec:** `docs/superpowers/specs/2026-10-15-web-admin-design.md` (read it first; this plan does not repeat its reasoning).

## Global Constraints

- Python 3.10+ (`tomli` fallback stays). New dependencies: `flask>=3.0`, `waitress>=3.0`, `tomli-w>=1.0`.
- Everything in the repo is English; every user-visible string goes through `locales/en-US.json` **and** `locales/pt-BR.json` (`tests/test_i18n.py` enforces equal keys). Shell messages use `MSG_*` in both `case "$LANGUAGE"` branches.
- The door must never say Free without knowing.
- `/kindle.png` is public and keeps its contract; every other known route needs a session; unknown paths are 404 for everyone.
- Every file the admin or `inkdoor password` writes is mode 600 regardless of umask (`files.write_private`).
- Calendar/task links never appear in any HTTP response, header, log line or exception message.
- Admin pages: no external resources, no inline `<script>` or `style=`; CSP `default-src 'self'; img-src 'self' data:; frame-ancestors 'none'; form-action 'self'; base-uri 'none'`.
- Session cookie `inkdoor_session`, `HttpOnly`, `SameSite=Strict`, `Path=/`, lifetime 7 days.
- Generated password: 16 chars from `23456789abcdefghjkmnpqrstuvwxyz`, groups of 4 joined by `-`; scrypt n=2^14, r=8, p=1, 16-byte salt; format `scrypt$<n>$<r>$<p>$<salt b64>$<hash b64>`.
- Login limit: per IP, after 5 failures wait 1, 2, 4 … 60 min; global slowdown 1 attempt/s; checked before scrypt.
- Outbound fetch: 5 MB cap, 30 s total deadline, ≤3 redirects, refuse loopback/link-local/unspecified on every hop; RFC 1918/ULA allowed.
- Admin "Test": ≤2 concurrent; Waitress `threads=8`; "Update now" at most once per 30 s.
- Host allowlist suffixes: `.local .lan .home .home.arpa .internal .localdomain .fritz.box .ts.net`, plus IP literals, `localhost`, single-label names, `[admin] allowed_hosts`.
- Kindle scripts and screen rules in `CLAUDE.md` still apply (1072×1448, 16 grays).

## Review Focus

Inputs the spec implies but does not spell out; each has a test in the owning task:

1. **Names and labels with quotes, accents, emoji or TOML-special characters** (`Empresa "Ltda" & Cia`, `Reunião 🎯`) must round-trip through the file and render escaped in HTML. → Task 6 and Task 11.
2. **Pasted links with surrounding whitespace, a trailing newline or an uppercase scheme** (`  HTTPS://…ics\n`) are trimmed and accepted; a link with `&` in its query is stored byte-for-byte. → Task 11.
3. **Tampered or incomplete forms** (non-integer hours, unknown style, unknown time zone, missing fields, a calendar index that no longer exists) show field errors or a reload message, never a 500. → Task 11 and Task 12.
4. **Removing the last busy calendar** makes the next render show "Knock first" (or the setup screen when nothing is left), never Free. → Task 11.
5. **A session that expires while a form is open**: the POST redirects to login and writes nothing. → Task 9.
